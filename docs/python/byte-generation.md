# Generate From The Selected Byte Model

**Source-only after 0.4.31.** Rust, Python and the standalone browser example use
the same bounded greedy loop. It uses the selected model's learned backbone,
geometry and routers without updating them or injecting an external score bias.
This is fixed-window byte generation, not an HF executor, sampling policy,
KV cache, network service or language-quality guarantee.

## Python

Start with a validated [artifact](byte-model-artifacts.md) or an active
[serving slot](byte-serving-gates.md). Each prompt must be exactly **T bytes**,
and there must be exactly **B prompts**, matching that model's compiled window.
There is no implicit padding, text encoding, truncation or EOS. For longer text,
the caller explicitly selects the initial T-byte window and records that choice.

```python
import json

# A model compiled for B=2, T=32. Encoding and window selection are explicit.
prompts = [b"SpiralTorch uses learned models.",
           b"Geometry shapes causal attention"]
assert all(len(p) == 32 for p in prompts)
result = json.loads(slot.generate_greedy(
    prompts, max_new_bytes=32, expected_generation=slot.generation,
))
assert result["artifact_id"] == slot.artifact_id
continuations = [bytes(row) for row in result["generated_bytes"]]
# Presentation only: replacement is not part of model decoding or stored bytes.
print(continuations[0].decode("utf-8", errors="replace"))

# The inference-only artifact owner exposes the same loop without a serving gate.
owner = artifact.restore_wgpu()
standalone = json.loads(owner.generate_greedy(prompts, max_new_bytes=32))
assert standalone["serving"] is None
```

Bounds are B=1..32, T=1..512 and 1..256 new bytes per row. Each step selects the
highest finite logit from the **last input position**, breaking exact ties with
the lowest byte ID, then shifts the context left and appends that byte. All
256 byte values are ordinary output, including NUL and invalid UTF-8 sequences.
There is no early stopping; `max_new_bytes` is the exact output length on success.

The loop recomputes the full causal window with positions and geometry reset to
zero at each step, as required by `fixed_window_frozen.v1`. It reuses the existing
forward/backward-tape infrastructure, but maps only B*256 next-byte logits per
step, rather than the full B*T*256 prediction. It still performs a GPU-to-host
readback and a new input upload per step. This is not a throughput improvement
claim or an optimized streaming decoder. A synthetic target byte supports the
existing batch layout; it is never used to select output or to report a loss.

## Ownership And Output

`spiraltorch.byte_corpus.generation.v1` includes the artifact ID, decimal revision,
inference policy, decoding policy, window shape, ordered prompt SHA256s, generated
byte rows and a SHA256 of each step's B*256 f32 little-endian next-logit values.
Serving calls additionally include the gate hash and decimal serving generation.
The JSON contains no prompts, weights, fake target CE or acceptance decision.
Generated bytes can still reveal private material; do not publish these results
automatically. A hash is not authentication or evidence of language quality.

A serving call requires the expected generation and rejects stale dispatches
before a forward. Its exclusive owner borrow prevents activation/rollback during
decoding. It does not consume candidate permits, alter rollback history or update
weights. An invalid input or failed decode returns an error, not a partial result.
Already-completed GPU work is not undone. Rolling back restores the prior model;
repeating an identical prompt is tested for identical bytes and logit hashes on
the same runtime. Different hardware/backends can change logits and greedy paths.
Admission on teacher-forced evaluation windows does **not** qualify free-running
generation quality or bound geometry/router health on every generated context.

## Rust And Browser

Rust calls `ResidentByteInference::generate_greedy(&prompts, count).await`, or
`ResidentByteServing::generate_greedy(&prompts, count, expected_generation).await`.
The returned `ByteCorpusGeneration` exposes `generated_bytes`, `artifact_id` and
`to_json`; it cannot be imported as a permit.

The standalone `resident_byte_learning_browser` client exposes
`await slot.generate_greedy(flatPrompts, count, generation)`, with a `Uint8Array`
of B*T bytes and a canonical decimal generation string. The Rust core owns byte
selection and window updates. `byte_generation_browser.html` checks actual
generation against a separate JS full-forward oracle before/after activation
and after rollback, using the same private `serving-input.json` as the
[serving qualification](byte-serving-gates.md). These are not yet packaged
`st-wasm` exports. CPU-only builds do not silently execute a CPU decoder.
