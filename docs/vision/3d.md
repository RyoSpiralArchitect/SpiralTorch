# 3D Perception in SpiralTorch

The 3D pipeline is composed of three building blocks that can be mixed together
depending on whether an experiment requires CPU-only execution or GPU-accelerated
volume rendering.

## Field representation

`st-vision` exposes a lightweight [NeRF](https://arxiv.org/abs/2003.08934)
implementation built on top of the existing `st-nn` layers:

- **Positional encodings** live in `st_vision::nerf::PositionalEncoding` and
  expand 3D coordinates using the familiar sinusoidal basis. The number of
  frequency bands and whether to keep the raw coordinates can be configured
  when the encoder is constructed.
- **Backbone** networks are composed of the standard SpiralTorch
  `Linear` + `Relu` layers orchestrated by `Sequential`. `st_vision::nerf::NerfField`
  produces density and RGB predictions in a single pass while remaining fully
  compatible with the module/optimizer interfaces defined in `st-nn`.

The field exposes helpers to assemble batched inputs, so downstream code can
feed separate position/direction tensors without duplicating bookkeeping logic.

## Dataset adapters

Multi-view datasets can be expressed through `st_vision::datasets::MultiViewFrame`
and `MultiViewDatasetAdapter`. Frames keep per-ray origins, directions, RGB
supervision and near/far bounds. The adapter defaults to uniform frame sampling,
then uniform-with-replacement ray sampling within the chosen frame. Optional
frame weights change the first distribution. Zero-weight frames are excluded,
including when the random threshold is exactly zero.

Admission validates all four tensor shapes, finite values and `near <= far`,
then takes owned row-major snapshots. Column-major/Chimera tensors are converted
by logical coordinates, not reinterpreted. Public frame/batch struct literals
are revalidated by the adapter, trainer and batch stacking paths. Later writes
to externally owned input storage cannot change admitted dataset snapshots.

## Training loop

`st_vision::nerf::NerfTrainer` implements a CPU-side training loop that
handles stratified sampling, volumetric compositing and gradient accumulation on
NeRF fields. The trainer plugs into the existing module optimisers by using the
`Module` trait methods (`zero_accumulators`, `backward`, `apply_step`) exposed by
`st-nn`.

Enable the Cargo feature `nerf` to use this trainer. Its integration contract is:

- Bounds are the parameter `t` in `origin + direction * t`. Density is per unit
  of `t`; directions are not implicitly normalized. Use unit directions for
  physical-distance bounds/density.
- Each sample represents the **full width** `(far - near) / samples_per_ray` of
  its bin. Stratification jitters only the evaluation point. Midpoints no longer
  discard half the interval; thin intervals have no artificial minimum width.
- A zero-width interval has exactly zero opacity. Reversed/nonfinite bounds,
  nonfinite coordinates and unrepresentable sampled coordinates are errors.
- Direction conditioning can be disabled (`direction_dims = 0`), but physical
  ray directions are still required. Otherwise direction/position dimensions
  must match. The standalone field can still use other feature layouts.
- Rendering and training share one black-background compositor and its MSE VJP.
  Interval arithmetic, optical depth, accumulation and loss reduction use f64;
  tensor outputs and parameter-gradient seeds remain f32. `expm1` preserves
  thin-slab opacity; opaque-slab derivatives retain the exponential term.
- The VJP keeps two f64 arrays for **one ray**, instead of four f32 arrays for
  every sample in the batch. Sample assembly writes directly into the field
  input instead of concatenating temporary position/direction tensors.
- Failed trainer calls do not consume sampler RNG state. Input/compositing
  errors precede gradient mutation. A later module backward/update error does
  **not** promise rollback of every parameter or gradient.

This intentionally changes rendering and updates relative to the historical
half-interval/minimum-width implementation. Saved parameter shapes are unchanged,
but old checkpoints can render differently under the corrected quadrature.
See `nerf_ray_integral.rs` for analytic rendering/update regressions, and the
private compositor tests for finite-difference VJPs. The fixed-seed, 20-step
`nerf_regression.rs` test checks progress, not scene convergence or image quality.

## Resident GPU rendering

`st_backend_wgpu::nerf::ResidentNerf` uses an existing `TensorDevice` on native
WGPU or browser WebGPU. It embeds its WGSL; browser calls need no filesystem.
It connects to an existing resident NN graph rather than introducing another
tensor family:

```rust,ignore
let nerf = ResidentNerf::new(graph.tensor_device().clone())?;
let rays = nerf.upload_rays(&rays)?; // NerfRay: origin, direction, near, far
let rgba = nerf.render_graph(
    &rays, 64, RaySampling::Stratified { seed: 17 }, &mut graph,
)?;
// rgba is still resident. Observe only at the desired boundary:
let snapshot = rgba.snapshot()?;
// Native: snapshot.read()?; browser: snapshot.read_async().await?;
```

The graph must accept `[rays, samples, 3]` and produce
`[rays, samples, 4]` with channels `[sigma, r, g, b]`. Positions are a zero-copy
view of `[x, y, z, t]`; widths have shape `[rays, samples]`. Sampler and
compositor write directly into owning tensors. Noncontiguous field inputs are
packed on GPU when necessary. There is no intermediate CPU readback.
`render_graph` uses `ResidentGraph::forward_tensor`: a first Linear stage reads
the position view directly with a row stride of four, avoiding the xyz packing
buffer and dispatch. A pointwise-first field still packs within that submission.
The graph's final stage writes an owning field tensor.
This avoids copying values through the graph's stable input/output workspace.
Shapes, device/queue identity and bin widths are checked before sampling;
already submitted work is not rolled back if a later graph operation fails.
For custom fields, `sample` and `composite` remain independently usable.
`render_graph_single_submission` is an explicit alternative: sampling, any packing,
NN and compositing share one submission. Typed host failures discard all recorded
work without changing the graph's input/output generations or binding keys;
private allocation caches may warm up. It is not rollback after GPU failure,
and numerical acceptance still requires the final guard. The default retains
three submissions: reducing their count alone is not a portable speedup.
The [matched direct-graph benchmark](../../benchmarks/nerf-direct-graph/README.md)
compares both connections, browser WebGPU, and eager PyTorch CPU/MPS with a
terminal readback. It is not a GPU-kernel-only or training benchmark.
The [submission comparison](../../benchmarks/nerf-single-submit/README.md)
isolates scheduling from the earlier stable-workspace copy reduction.
The [row-input comparison](../../benchmarks/nerf-row-input/README.md) holds
submission count fixed and compares forced packing with direct row addressing.
It preserves all conditions, including the already-contiguous 1x1 control.

Bounds and full bin widths follow the same `t` convention as the CPU trainer.
The seeded GPU sampler uses a counter hash, not the CPU trainer's `StdRng`
stream; equal integer seeds do not imply equal CPU/GPU sample points.
Compositing applies ReLU to density, leaves signed radiance unclamped, and uses
a black background. Thin opacity uses a small-depth polynomial; optical depth,
RGB and opacity use integer-defined rounded compensated f32 sums. This is not
an f64 implementation or an f64-equivalence guarantee over extreme ranges.

Host admission rejects reversed/nonfinite bounds, unrepresentable f32 spans,
positive subnormal bin widths, device/queue mismatches and wrong field shapes.
Zero-width rays are valid. GPU arithmetic failures and inherited tensor errors
reject the eventual snapshot, even if a later operation masks a nonfinite value.
Submission alone is not numerical acceptance. Held draws/results are immutable
and survive later dispatches and graph/engine drops.

This API is **forward-only**. `NerfTrainer` still owns the separate CPU sampler,
compositor and VJP above. No automatic `NerfField`/positional-encoding migration,
NeRF GPU VJP, Python wrapper or general-purpose JavaScript class is claimed.
The [native/browser fixture](../../benchmarks/nerf-resident-wgpu/README.md) uses
an affine resident NN field and an independent PyTorch numerical control.

The older file-based `create_sampling_pipeline` and
`create_raymarch_pipeline` constructors retain their legacy entry points and
padded buffer layouts. The latter expands the shared rounded-add helper:
manual shader consumers should use `shader_sources::nerf_raymarch_source()`,
not compile the unexpanded `nerf_raymarch.wgsl` template alone.
Legacy entry points have no guard binding: an invalid ray poisons all its sample
positions/widths, and an invalid integral emits NaN RGBA rather than a finite
partial result. Checked resident entry points instead propagate tensor guards.
