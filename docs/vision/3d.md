# 3D Perception in SpiralTorch

The 3D pipeline is composed of three building blocks that can be mixed together
depending on whether an experiment requires CPU-only execution or GPU-accelerated
volume rendering.

## Field representation

`st-vision` exposes a lightweight [NeRF](https://arxiv.org/abs/2003.08934)
implementation built on top of the existing `st-nn` layers:

- **Positional encodings** live in `st_vision::nerf::PositionalEncoding` and
  expand 3D coordinates using the familiar sinusoidal basis. The number of
  frequency bands and whether to keep the raw coordinates can be configured
  when the encoder is constructed.
- **Backbone** networks are composed of the standard SpiralTorch
  `Linear` + `Relu` layers orchestrated by `Sequential`. `st_vision::nerf::NerfField`
  produces density and RGB predictions in a single pass while remaining fully
  compatible with the module/optimizer interfaces defined in `st-nn`.

The field exposes helpers to assemble batched inputs, so downstream code can
feed separate position/direction tensors without duplicating bookkeeping logic.

## Dataset adapters

Multi-view datasets can be expressed through `st_vision::datasets::MultiViewFrame`
and `MultiViewDatasetAdapter`. Frames keep per-ray origins, directions, RGB
supervision and near/far bounds. The adapter defaults to uniform frame sampling,
then uniform-with-replacement ray sampling within the chosen frame. Optional
frame weights change the first distribution. Zero-weight frames are excluded,
including when the random threshold is exactly zero.

Admission validates all four tensor shapes, finite values and `near <= far`,
then takes owned row-major snapshots. Column-major/Chimera tensors are converted
by logical coordinates, not reinterpreted. Public frame/batch struct literals
are revalidated by the adapter, trainer and batch stacking paths. Later writes
to externally owned input storage cannot change admitted dataset snapshots.

## Training loop

`st_vision::nerf::NerfTrainer` implements a CPU-side training loop that
handles stratified sampling, volumetric compositing and gradient accumulation on
NeRF fields. The trainer plugs into the existing module optimisers by using the
`Module` trait methods (`zero_accumulators`, `backward`, `apply_step`) exposed by
`st-nn`.

Enable the Cargo feature `nerf` to use this trainer. Its integration contract is:

- Bounds are the parameter `t` in `origin + direction * t`. Density is per unit
  of `t`; directions are not implicitly normalized. Use unit directions for
  physical-distance bounds/density.
- Each sample represents the **full width** `(far - near) / samples_per_ray` of
  its bin. Stratification jitters only the evaluation point. Midpoints no longer
  discard half the interval; thin intervals have no artificial minimum width.
- A zero-width interval has exactly zero opacity. Reversed/nonfinite bounds,
  nonfinite coordinates and unrepresentable sampled coordinates are errors.
- Direction conditioning can be disabled (`direction_dims = 0`), but physical
  ray directions are still required. Otherwise direction/position dimensions
  must match. The standalone field can still use other feature layouts.
- Rendering and training share one black-background compositor and its MSE VJP.
  Interval arithmetic, optical depth, accumulation and loss reduction use f64;
  tensor outputs and parameter-gradient seeds remain f32. `expm1` preserves
  thin-slab opacity; opaque-slab derivatives retain the exponential term.
- The VJP keeps two f64 arrays for **one ray**, instead of four f32 arrays for
  every sample in the batch. Sample assembly writes directly into the field
  input instead of concatenating temporary position/direction tensors.
- Failed trainer calls do not consume sampler RNG state. Input/compositing
  errors precede gradient mutation. A later module backward/update error does
  **not** promise rollback of every parameter or gradient.

This intentionally changes rendering and updates relative to the historical
half-interval/minimum-width implementation. Saved parameter shapes are unchanged,
but old checkpoints can render differently under the corrected quadrature.
See `nerf_ray_integral.rs` for analytic rendering/update regressions, and the
private compositor tests for finite-difference VJPs. The fixed-seed, 20-step
`nerf_regression.rs` test checks progress, not scene convergence or image quality.

## GPU kernels

`st-backend-wgpu` now ships WGSL compute shaders that cover the most common
volumetric operations:

- `nerf_volume_utils.wgsl` generates stratified sample positions and segment
  lengths for a set of rays.
- `nerf_raymarch.wgsl` composites per-sample density/radiance predictions into
  final RGB and accumulated opacity buffers.

`crates/st-backend-wgpu/src/nerf.rs` exposes convenience constructors to load
these pipelines, so the higher level runtime can plug them into render graphs
without managing shader lifetimes manually.

These GPU pipeline constructors are separate from `NerfTrainer`; its sampler
and compositor do not dispatch these WGSL kernels. The CPU/WASM ray contract above
does not establish GPU-kernel parity or a fully resident NeRF training path.
