## Primary Questions And Acceptance

Compare width16 versus width32 at256 and1024 accepted updates, retaining every
seed and all three arms. The512 snapshot is an intermediate diagnostic, not a
new endpoint chosen after results. Report CE minus the seen-training-only
add-one-smoothed bigram baseline for development and the monitor probe.
Primary quality interpretation asks whether the conditional baseline is beaten
consistently; a lower model CE by itself is insufficient.

Select each case only among its four saved snapshots using the shared Rust rule
(lowest development CE, earliest exact tie). Complete every selection before
reading probe outputs. The selected artifact and final artifact are both kept;
selection is neither serving promotion nor proof of training.

Generate32 new bytes per row from the same first two T32 development prompts at
all72 saved model/cursor combinations. No decoding change or prompt search.
Keep raw generated bytes and prompt hashes, space and repetition fractions,
and check native greedy decoding against an independent full-forward oracle.
Evaluate the monitor probe at the256/512/1024 snapshots to expose the complete
learning curves, but never use probe results to choose snapshots or settings.

Independent CPU float32 PyTorch uses each exact request. Keep existing strict
elementwise, geometry-delta and moment gates unchanged. Failed numerical
qualification stays failed and is retained; it cannot establish quality or
promote a model. Reject nonfinite updates and changed frozen state. There is
no automatic restart of a claimed run. Run GPU studies serially.

Public artifacts contain all conditions' metrics, generated outputs, validation
and hashes. Corpus requests, model weights, moments, artifacts and wheels stay
in private owner-only storage. No new corpus acquisition, provider requests,
