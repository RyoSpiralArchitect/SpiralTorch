# Language Capacity And Learning Budget

This bounded experiment keeps Rust as the learning, geometry, saved-model
selection and inference owner. Python prepares paired inputs and measures the
existing runtime against independent CPU float32 PyTorch. It is not a pretrained
LLM fine-tune, a distributed scheduler, a release or a serving promotion.

The [fixed plan](PLAN.md) compares widths16/32 and saved update budgets
0/256/512/1024 with seeds11/29/47. Each seed has ordinary attention, learned
Poincare geometry and identically initialized frozen geometry. All conditions
use the same data order, optimizer controls and greedy decoder. Width changes
head dimension and capacity; this is equal data/update count, not equal compute.
Previously inspected repository documents are development/monitor data, not an
untouched language benchmark.

## Outcome: Complete, But Not Numerically Qualified

All 18 models completed 1024 accepted updates (18432 model updates total), with
65536 training target-byte presentations per model. These are repeated corpus
presentations, not 65536 unique bytes. The original 256-step width16 models are
reproduced exactly in all 9 cases: weights, first/second moments, training losses
and development batch losses have identical float32 bits.

However, **all 6 studies fail the unchanged full 1024-step numerical gate**.
Across all 18 cases, 139 parameter components exceed
`3e-6 + 5e-5 * abs(reference)`: 117 in the Key slice of QKV bias, 1 in token
embeddings, and 21 in output-head weights. No failing QKV bias component is in
Query or Value. The largest parameter difference is 1.13972e-5. All measured
training/development scalar-loss differences are within the original gate
(maximum 5.72205e-6), and both moment elementwise/relative gates pass in the
post-hoc localization. None of this overrides the failed parameter gate.

See [numerical-diagnostics.json](numerical-diagnostics.json) for every parameter
family, including failures outside Key bias. The Key concentration motivates
checking its analytically redundant direction separately from accumulated
rounding in meaningful weight coordinates. That is a follow-up hypothesis,
not evidence that all differences are harmless, and not permission to omit
those coordinates or loosen the original tolerance.

## Diagnostic Language Observations

The following are **unqualified native observations**, not accepted evidence of
a geometric advantage. Means over 3 seeds at 1024 updates, CE in nats/byte:

| Width | Arm | Development | Monitor Probe |
| ---: | --- | ---: | ---: |
| 16 | Ordinary | 3.089274 | 2.912371 |
| 16 | Learned Poincare | 3.081724 | 2.900313 |
| 16 | Frozen Poincare | 3.089573 | 2.908531 |
| 32 | Ordinary | 3.026519 | 2.706605 |
| 32 | Learned Poincare | 2.991102 | 2.653081 |
| 32 | Frozen Poincare | 3.008241 | 2.670561 |
| n/a | Seen-training-only bigram | 3.063437 | 2.817312 |

The width32 observations fall below bigram on both splits in every arm/seed;
width16 does not beat it on the monitor probe. Learned geometry is lower than
frozen geometry on both splits in all six paired seed/width conditions, but
the failed numerical gate prevents interpreting that as validated efficacy.
All 256/512/1024 observations and paired deltas are retained in
[results.json](results.json), and both engines' full training/development
trajectories are in [learning-curves.json](learning-curves.json).

The bigram comparison changes with exposure: its development CE is 3.282078 at256
and 3.063437 at1024, while probe CE is 3.097516 and 2.817312 respectively. Each
baseline sees only the same training prefixes as that saved model, with fixed
add-one smoothing. Publication recomputes these values from pinned inputs.

Free-running language remains repetitive. For example, width32/seed11 learned
geometry produces `the the there the the the the th` on the first fixed prompt.
At1024 the mean repeated-bigram fraction is 0.683 for both width32 ordinary and
learned geometry (frozen 0.694). This is lower than the roughly 0.85 seen at
width16/256, but not coherent prose. Every generated byte is retained, including
initialization outputs; no sampler change or favorable-prompt selection was made.

## Operational Checks

- All 18 cases select1024 among saved cursors0/256/512/1024. No early-selection
  benefit is claimed; this is development selection, not deployment admission.
- All 72 saved models restore and reproduce their scheduled first-batch CE
  exactly as float32. All 72 greedy sequences and next-logit hashes match the
  independent full-forward oracle.
- Saved weights, moments, clocks and histories bind to their segment reports.
  This is not a new uninterrupted-versus-resumed experiment.
- Numerical status on every saved-cursor row refers to the **whole1024-update
  study**. It is not a separately measured failure at each earlier cursor.
- The new harness has 28 passing tests; the reused segment runner and previous
  baseline/generation helper have 3 and 5 passing tests. The hardened launcher's
  six-input Rust portable preflight passed without additional training.
- Independent read-only review found and corrected launch input/runtime binding,
  checkpoint-cursor, historical-repeat, qualification-runtime and publication
  baseline gaps. The failed initial preflight, test logs and original run receipts
  remain private with [public hashes](private-receipts.json).

No new browser matrix, release upload, provider call, serving activation or
backend speed comparison was performed. Raw corpus, weights, moments and model
artifacts stay private. The first preflight attempt rejected dictionary insertion
order as parameter identity; canonical key ordering fixed that false rejection
before training, without changing numeric values or signed-zero distinctions.

Next: localize the long-run parameter discrepancy at the Rust Attention/AdamW
boundary with focused invariance and update tests, then rerun a fixed diagnostic
cohort before enlarging the corpus or claiming a language-quality improvement.

## Reproduction

Use a current-source WGPU Python build (the private qualification wheel retains
0.4.31 metadata; it must not be uploaded to that immutable PyPI version).
Reference execution separately requires CPU PyTorch. Use absolute paths to a
fresh owner-only directory, never an existing failed run. The commands below
assume the repository root and the retained previous pilot directory `HISTORICAL`.
These private companions are required to reproduce the exact historical-repeat
check. Their public hashes are not substitutes for their contents.

```bash
umask 077
mkdir -m 700 "$RAW"
cp benchmarks/results/2026-10-16-language-capacity-budget/PLAN.md "$RAW/PLAN.md"
for width in 16 32; do
  for seed in 11 29 47; do
    case_dir="$RAW/w${width}-seed${seed}"
    mkdir -m 700 "$case_dir"
    python -I -B tools/byte_corpus_study.py prepare "$case_dir/paired" \
      --revision 02f211f72a029ce6455aed2c706ca35989490c03 \
      --train-doc docs/byte_corpus_learning.md \
      --train-doc docs/byte_corpus_calibration.md \
      --validation-doc docs/resident_adamw.md \
      --seed "$seed" --batch 2 --steps 32 --width "$width" \
      --hidden "$((width * 2))" --heads 2 --blocks 1 --updates 1024 \
      --checkpoint-every 64 --validation-batches 32 --rate .001 \
      --frozen-geometry-control
    python -I -B tools/byte_corpus_study.py bind-optimizer \
      "$case_dir/paired/request.json" examples/configs/byte_corpus/adamw.json \
      "$case_dir/request.json"
  done
done
EXP=benchmarks/results/2026-10-16-language-capacity-budget
python -I -B "$EXP/launch.py" preflight --repo "$PWD" --root "$RAW" \
  --historical "$HISTORICAL"
python -I -B "$EXP/launch.py" reference --repo "$PWD" --root "$RAW"
python -I -B "$EXP/launch.py" native --repo "$PWD" --root "$RAW"
python -I -B "$EXP/qualify.py" select --repo "$PWD" --root "$RAW" \
  --historical "$HISTORICAL"
python -I -B "$EXP/qualify.py" evaluate --repo "$PWD" --root "$RAW" \
  --historical "$HISTORICAL"
python -I -S -B "$EXP/diagnose.py" --repo "$PWD" --root "$RAW" \
  --output "$RAW/numerical-diagnostics.json"
mkdir "$PUBLIC"
python -I -B "$EXP/publish.py" "$RAW" "$PUBLIC" --repo "$PWD" \
  --historical "$HISTORICAL"
```

All six studies must complete before selection/evaluation. Numerical failure
is retained with its original strict criterion and diagnostic-only status;
the result is not converted to a pass by dropping a seed or relaxing tolerance.
Selection checks actual saved states, never an unsaved validation minimum.
Every saved model is restored and generates bytes; the full-forward oracle is
independent of the production greedy loop. The previously inspected monitor
probe is opened only after every selected artifact is fixed and validated.

The hardened launcher resolves paths before changing a child's working
directory, verifies the native extension inside the isolated execution child,
and binds execution to the exact checked request bytes. Inputs and source files
are rechecked around each condition. Failed claims are retained; there is no
automatic retry. These are accidental-mixup safeguards, not signed runtime
attestation or protection against a malicious local process.

The original recorded run began before this launcher hardening. Its unchanged
preparation manifest binds the original launcher, retained privately as
`launch-source.py`. Read-only qualification can verify that archived source;
new execution cannot use that fallback. The run used absolute paths and an
isolated parent. No new per-child attestation is retroactively asserted for it.
The model runner, reference mathematics, requests and loaded native extension
were not changed to obtain different experiment outcomes.

`diagnose.py` is an explicitly post-hoc localization tool, not a new numerical
gate. Publication recomputes its errors from the retained outputs. Individual
parameter values embedded in comparison exceptions are redacted from the public
selection record, with the original private record/error hashes retained.
