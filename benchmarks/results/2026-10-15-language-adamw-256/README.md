# AdamW Language Learning And Saved-Model Selection

The shared Rust runner completed **three seeds x three arms x 256 updates**.
Python and WASM now select actual saved model artifacts with the same Rust
development-loss rule, preserving geometry, optimizer history and exact source
identity. This is not a pretrained LLM FT run or a production promotion.

## Learning Result, Including Its Limit

The [predeclared plan](PLAN.md) fixed seeds 11/29/47, ordinary attention, learned
Poincare geometry and identically initialized frozen geometry. B2/T32, width16,
hidden32, two heads, one block; fixed AdamW rate 0.001. Each case saw 16384 training
target-byte presentations; development and separate probe each contain 2048
target bytes from different repository documents. These are related technical
documents, not an untouched broad language benchmark.

Mean CE in nats per byte, lower is better, across the three seeds at 256 updates:

| Model | Development | Separate Probe |
| --- | ---: | ---: |
| Ordinary | 3.406061 | 3.459236 |
| Learned Poincare | 3.399698 | 3.445955 |
| Frozen Poincare | 3.400240 | 3.447008 |
| Training-only unigram | 3.471067 | 3.538551 |
| Training-only bigram | **3.282078** | **3.097516** |

Learned geometry has lower development and probe loss than both controls in
every seed, but the learned-versus-frozen difference is very small. Most of the
geometric-arm difference is already present with frozen geometry; this does not
establish a robust learned-geometry advantage. All nine models beat unigram,
but **all remain worse than bigram**. No optimizer tuning or equal-compute claim
is made. Earlier SGD experiments used different recipes and are not a matched
optimizer comparison.

Free-running output remains poor. For example, seed29 learned geometry produces
`re s s s s arererererererererere` on the first predeclared prompt. Other seeds
mostly repeat spaces, `e` or `t`. At the final cursor the mean within-row repeated
bigram fraction is about0.85 in every arm; lower CE has not produced coherent
language. All 36 generation records, including initialization and failures of
language quality, are retained in [results.json](results.json). No sampling
penalty, prompt search or favorable-example selection was used.

## What The MLOps Path Now Does

Saved cursors were 0/64/128/256. The [Rust selector](../../../docs/byte_corpus_checkpoint_selection.md)
chooses the lowest development CE **among available saved weights**, with ties
going to the earliest supplied revision. It validates every case and unchanged
history prefixes, then returns the existing immutable model artifact. It cannot
select an unsaved intermediate minimum. Development choice is not a serving gate.

All nine cases selected 256 in this run, so selected-versus-final probe results
coincide; no selection uplift is claimed. Unit tests separately cover a genuine
earlier winning snapshot, exact ties, unsaved minima and forked histories.
Probe bytes/losses were read only after all selected artifacts were fixed.

- Native WGPU versus independent CPU float32 PyTorch passed all 9 cases with
  unchanged elementwise, geometry-delta and AdamW-moment tolerances.
- Four all-case checkpoints bind exact weights, moments, clocks and history to
  their segment reports. This was one segmented run, **not** a separate exact
  uninterrupted/resumed experiment; prior short resume qualification is separate.
- Fresh-process artifact restoration reproduced the scheduled first-batch CE
  exactly as float32 at all 36 saved case/cursor combinations.
- All 36 greedy generations match an independent full-forward decoder, including
  every generated byte and next-logit hash. This checks execution, not quality.
- Actual browser WASM selection matched every native decision and artifact ID.
  Empty, reversed and foreign-request candidates rejected. The first selected
  artifact then executed on BrowserWebGpu with the same measured first-batch CE.
  Only this one selected artifact's browser inference was measured in this pilot.

See [comparison.json](comparison.json), [selection.json](selection.json),
[browser-selection.json](browser-selection.json) and the
[private receipt hashes](private-receipts.json). Full requests, corpus payloads,
weights, moments, artifacts and source-built wheels remain private. PyPI 0.4.31
was not changed or uploaded; private qualification wheels retain that metadata.

## Reproduce

Build current-source WGPU bindings in an isolated environment. Use a fresh
owner-only directory; existing output directories are not retry targets.

```bash
python -I -B tools/byte_corpus_study.py prepare "$RAW/paired" \
  --revision 02f211f72a029ce6455aed2c706ca35989490c03 \
  --train-doc docs/byte_corpus_learning.md \
  --train-doc docs/byte_corpus_calibration.md \
  --validation-doc docs/resident_adamw.md \
  --seed 11 --seed 29 --seed 47 --batch 2 --steps 32 --width 16 \
  --hidden 32 --heads 2 --blocks 1 --updates 256 --checkpoint-every 64 \
  --validation-batches 32 --rate .001 --frozen-geometry-control
python -I -B tools/byte_corpus_study.py bind-optimizer "$RAW/paired/request.json" \
  examples/configs/byte_corpus/adamw.json "$RAW/request.json"
cp benchmarks/results/2026-10-15-language-adamw-256/PLAN.md "$RAW/PLAN.md"
python -I -B tools/run_byte_corpus_segments.py "$RAW/request.json" "$RAW/native" \
  --stop 0 --stop 64 --stop 128 --stop 256
python -I -B tools/byte_corpus_study.py reference "$RAW/request.json" "$RAW/torch.json"
python -I -B tools/byte_corpus_study.py compare "$RAW/request.json" "$RAW/torch.json" \
  "$RAW/native/report-256.json" "$RAW/comparison.json"
python -I -B benchmarks/results/2026-10-15-language-adamw-256/qualify.py select \
  --repo "$REPO" --root "$RAW"
python -I -B benchmarks/results/2026-10-15-language-adamw-256/qualify.py evaluate \
  --repo "$REPO" --root "$RAW"
```

Reference execution uses a separate Python environment with PyTorch; it never
imports SpiralTorch. Native execution here used the qualified source wheel from
parent 02f211f72; selection/inference used the new source wheel. The math/optimizer
implementation is unchanged between them. No native-only geometry or scoring
reimplementation was added. For the browser, build the existing
`resident_byte_learning_browser` example and wasm-bindgen web package, then serve
`crates/st-nn/tests/byte_selection_browser.html` on loopback with the matching
request, four checkpoints, segment reports and selection record.

The next learning question is how to beat the seen-training-only conditional
baseline and improve generated behavior, not how to hide repetition through
postprocessing. This pilot gives a reusable model-selection handoff, not that
missing language-quality result.
