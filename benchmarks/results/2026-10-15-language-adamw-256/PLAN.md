# Predeclared AdamW Language Budget

This is an exploratory language-learning and checkpoint-selection pilot, not
an untouched final benchmark, optimizer-tuned comparison or serving promotion.
Run source: parent 02f211f72a029ce6455aed2c706ca35989490c03 plus the source hashes
recorded with the receipts. No corpus downloads, HF weights or provider calls.

- Source documents at commit 02f211f72a029ce6455aed2c706ca35989490c03.
- Train: docs/byte_corpus_learning.md and docs/byte_corpus_calibration.md.
- Development: docs/resident_adamw.md; previously inspected, not final test data.
- Seeds 11, 29, 47; ordinary, learned Poincare and frozen Poincare for every seed.
- B2, T32, width16, hidden32, heads2, one block, four geometry coordinates.
- 256 updates, fixed rate0.001, validation every64, 32 distinct validation batches.
- AdamW beta1=0.9, beta2=0.999, epsilon=1e-5, ordinary decay0.01, geometry decay0.
- No rate tuning, sampling tuning, early stopping, clipping or schedule.
- Save all cases at cursors0,64,128,256. Preserve every condition and failure.
- Select each case independently among those saved cursors by lowest development
  mean CE, with exact ties resolved to the earliest revision. Never rank seeds
  or remove an arm. Historical intermediate losses without saved weights are
  not eligible. Selection is not promotion or proof of training.
- Use the shared Rust selector; Python and browser transport its decision.
- Evaluate each selected artifact and each final artifact on a separate probe:
  docs/byte_corpus_query_controls.md, 32 evenly spaced complete B2/T32 batches.
  Probe document content/losses are not read for checkpoint selection. The probe
  is related repository prose, not an independent broad language benchmark.
- Greedy generation from the first two T32 prompts of the development windows,
  32 new bytes per row, same prompts at each saved cursor, all nine cases.
  Preserve generated bytes, repetition and space fractions; no prompt search.
- Compare actual native WGPU against independent CPU float32 PyTorch on the
  exact request. Keep existing strict tolerances, including moments/deltas;
  report a failure rather than relaxing them for a longer trajectory.
- Record seen-training-only unigram/bigram baselines; never fit probe labels.
- Raw requests, checkpoints, artifacts and wheels stay in a private owner-only
  directory. Publish results, validation, source hashes and reproduction only.

This nine-case run has 16384 training target-byte presentations and 2048
development target bytes per case. Equal data/update count is not equal compute
or parameter count. Historical SGD studies differ and are context, not a matched
optimizer control. Numerical qualification and loss improvements do not imply
free-running language quality or a geometry advantage.
