# Learning Budget: 128 To 512 Updates

All 25 geometric control arms completed a fresh, one-seed byte-LM run through
128, 256 and 512 accepted updates per model. Python called the Rust/WGPU runner;
an independent CPU-float32 PyTorch run used the identical request. No thresholds
were relaxed. This is not pretrained-model FT, a speed benchmark, or a production
promotion. It follows the [nine-model frozen diagnosis](../2026-10-15-language-learning-diagnosis/README.md).

## What Changed

The within-run variable is training budget, not architecture, sampling or prompt
selection. Seed 11 was the first historical seed, not chosen as a winner. All
ordinary, frozen-geometry, metric, learned/frozen mixture and query controls
remain in the study. B2, T32, width 16, hidden 32, two heads, one block, SGD 0.05;
training-only RMS preparation uses batches 0/1/2/3. See the pre-run [plan](PLAN.md).

The first preparation attempt required exact historical initial bits and stopped
before training: fresh Fisher-related calibration differed slightly. We retained
that failed [plan](historical-plan.md) and [all initial differences](historical-differences.json).
The accepted plan compares checkpoints **within the new run**, not an allegedly
identical extension of the old run. Rust preparation packets were revalidated;
no historical optimizer clock or checkpoint was transplanted.

Each model saw 32768 target-byte presentations at 512 updates, from the same
pinned repository documents. Validation remained the same 2048 target bytes.
These are related documents and repeatedly inspected validation data, not an
independent final language benchmark. Raw corpus, weights, preparation packets
and checkpoints remain private; their hashes are in the public records.

## Learning And Generation

Cross-entropy in nats per byte, lower is better. Both baselines use only the
training transitions seen through each checkpoint; no future or validation
labels fit them. Add-one smoothing is fixed, not tuned on validation.

| Updates | Ordinary | Poincare/chord query trained | Query frozen | Unigram | Bigram |
| --- | ---: | ---: | ---: | ---: | ---: |
| 128 | 3.560238 | 3.560208 | 3.560208 | 3.400582 | 3.436886 |
| 256 | 3.409579 | 3.397698 | 3.397698 | 3.387612 | 3.219298 |
| 512 | 3.239462 | 3.231052 | 3.231052 | 3.381303 | 3.064835 |

At 512 updates all 25 models beat unigram but remain worse than the simple
conditional bigram baseline. Geometry variants have small loss differences in
this one seed; learned-query versus frozen-query differences remain extremely
small. This does not establish a robust geometry or query-learning advantage.

On the same two preselected 32-byte prompts, all three displayed models produce
the same greedy continuations at every checkpoint. No sampling, penalties or
prompt search was added:

| Updates | Output row 0 | Output row 1 | Spaces / 64 generated bytes |
| --- | --- | --- | ---: |
| 128 | 32 spaces | `e` + 31 spaces | 63 |
| 256 | 32 spaces | `e` + 31 spaces | 63 |
| 512 | 32 spaces | `ant` + 29 spaces | 61 |

Teacher-forced improvement therefore does **not** qualify free-running language.
The complete nine generation receipts, every arm's validation trajectory and
all per-batch losses are retained in [qualification.json](qualification.json).
No winner, checkpoint or failure was removed.

## Verification

- All 25 arms pass the unchanged independent Torch comparator: per-value
  `atol=3e-6`, `rtol=5e-5`, geometry-delta relative-L2 gate `0.002`.
- Maximum training and held-out batch-CE errors are both `1.430511474609375e-6`;
  maximum final-parameter absolute error is `9.5367431640625e-7`.
- Maximum qualified geometry-delta relative-L2 error is about `5.713e-6`.
  Frozen geometry/router parameter bits are checked, not inferred from metadata.
- All three checkpoints' 25 cases are bound to the evaluated segment reports:
  tensor shapes/float32 bits, training histories and validation losses. Earlier
  history prefixes remain unchanged across resume.
- Each of nine Rust generation results matches a separate pristine-owner
  full-forward oracle, including every next-logit hash and generated byte.
- Six qualifier tests cover checkpoint-weight/history tampering and seen-only
  baselines; three launch-claim tests cover duplicate-run prevention. Independent
  read-only review findings were fixed before final qualification.

The run consumed 12800 native accepted model updates plus a separate 12800-update
CPU reference. Native segments took roughly 2048/2014/4044 seconds, but these are
operational observations, not a controlled speed comparison. The native process
was sampled for one second; no backend bottleneck claim follows from that sample.

The first native run started before a reviewer identified duplicate-launch risk.
It was adopted into an atomic claim after process verification, without restart
or repeated updates. The record explicitly says `before_gpu_launch=false`.
Future launches use `run_once.py`; a failed run keeps its claim and requires an
explicit recovery decision, not an automatic second budget consumption.

## Reproduce With Retained Private Inputs

The files here are the scripts used for this specific bounded experiment, not
a general scheduler or arbitrary-model API. The historical preparation scripts
and plans remain unchanged for provenance. `adopt_preparation.py` records this
experiment's known non-identical historical initialization; do not use that
fixed claim to certify unrelated preparations.

Start with the retained `v3/request.json`, `v5-packet.json`, `v7-packet.json`,
`v8-packet.json`, each corresponding `*-request.json`, and the historical v8
request. The source document revision and prepare command are the existing
[corpus protocol](../../../docs/byte_corpus_learning.md), with seed 11,
`--updates 512 --metric-geometry-control`. Rust's Python preparation chain is
shown in [the Python guide](../../../docs/python/byte-corpus-studies.md#geometry-controls).
Keep exact JSON bytes. The accepted fresh run uses [PLAN.md](PLAN.md) and the
request digest recorded in [prepared.json](prepared.json).

For a **new private run directory**, after validating/adopting those retained
preparation packets, use the launch guard rather than invoking the raw runner:

```bash
"$SOURCE_WHEEL_PYTHON" -I -B run_once.py --runner "$RUNNER" --repo "$REPO" \
  --historical "$HISTORICAL_REQUEST" --output "$PRIVATE"
"$TORCH_PYTHON" -I -B "$REPO/tools/byte_corpus_study.py" reference \
  "$PRIVATE/request.json" "$PRIVATE/torch.json"
"$SOURCE_WHEEL_PYTHON" -I -B qualify.py --repo "$REPO" --pilot "$PRIVATE" \
  --gate "$PINNED_SERVING_GATE"
python -I -S -B test_run_once.py -v
python -I -S -B test_qualify.py -v
```

`$RUNNER` is the unchanged `run_budget.py` bound in preparation metadata. Do not
rerun against this original directory or remove its claim. Qualification writes
are exclusive too; inspect partial evidence before retrying any failed check.
No package publication or serving-model activation occurred.

## Next Learning Rail

This pilot supports strengthening the ordinary learning path before multiplying
geometry configurations. The resident byte model currently exposes stateless
SGD; the host-side Z-space meta-optimizer's Adam transition is a different
control-plane operation, not resident Adam for model weights. A stateful model
optimizer must own moments, rejected-step behavior and exact checkpoint/resume
alongside learned geometric parameters. Keep ordinary and geometric controls
paired, and retain generated-behavior checks rather than promoting on CE alone.
