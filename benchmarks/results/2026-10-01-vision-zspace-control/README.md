# Shared Resident Z-Space Control

Rust parameter-side Z-space control now reaches actual resident ConvNeXt SGD
through the same Python and WASM trainer. This result exercises control delivery,
replay rejection and restart, not an adaptive policy or a learning-quality gain.

## Conditions And Results

The model has 24 parameter tensors / 456 f32 values, two stages `[2,3]`, depths
`[1,1]`, 3x4x4 inputs, 2x2 patches and two classes. Twenty synthetic images use
batch size two, shuffle seed 17, transform seed 29 and model seed 43. One
immutable sample has an invalid class, intentionally rejecting ten updates.
Each run has 100 attempted updates, split after attempt 37 for restart.

Five complete reports are generated by the Rust meta-optimizer. Before zero-based
attempts `0,9,36,37,64`, the prescribed absolute scales are
`0.5,1.25,0.75,1.0,0.5`. Every message is sent twice to check non-compounding.
This sequence is externally prescribed, not derived from the model's training
signal. The consumer checkpoint preserves the applied scale and replay clock;
the producer's latent state is deliberately outside this measurement.

| Nominal schedule | Accepted / rejected | Native process restart | Fresh-document browser restart | Python -> browser maximum scaled weight error | Browser -> Python maximum scaled weight error |
| --- | --- | --- | --- | --- | --- |
| Constant `0.001` | 90 / 10 | Exact trajectory and final checkpoint | Exact trajectory and final checkpoint | 0 | 0 |
| Warmup/cosine `0.002 -> 0.0001`, warmup 10, total 100 | 90 / 10 | Exact trajectory and final checkpoint | Exact trajectory and final checkpoint | 0 | 0 |

Each schedule has separate browser control, prefix, resume and native-prefix
continuation phases, eight browser cases in total. Native control/prefix/resume
use distinct processes. Each resumed sequence contains the same input bits,
labels, effective-rate bits and acceptance decisions. Cross-runtime checks
cover every weight with a predeclared scaled-error bound of `2e-4`; the zero
observed here is not a general cross-device bitwise guarantee.

Native reports identify Apple M4 / Metal / IntegratedGpu. The actual in-app
browser reports BrowserWebGpu / Other / an empty adapter name. Its GPU model is
not inferred. Browser restart closes and recreates the document/WASM instance,
not the OS browser process or a power-loss recovery.

## Other Regression Evidence

- Rust controlled SGD matches every weight from explicit half-rate SGD and
  differs from the unscaled control. Duplicate messages never compound.
- Stale/conflicting/tampered controls, pending updates, overflow/underflow and
  corrupted/downgraded checkpoints fail without partial trainer mutation.
- Rejected updates retain every weight, the schedule and the applied control;
  they still consume their input batch.
- Previous-build plain-SGD checkpoints from the client fixture round-trip
  byte-for-byte and continue the same 63 steps under the new native build.
- `st-nn`: 737 passed. `st-vision`: 108 passed / one ignored with real WGPU
  opted in; 78 CPU tests passed. All five Python control tests ran and passed.
- A fresh WASM release build and generated/shipped TypeScript contracts passed.
  Rust formatting and strict scoped Clippy passed after removing two needless
  borrows on one existing ConvNeXt test line; the original lint failure is retained.

## Provenance And Reproduction

Runtime sources are captured by `2c911269a018d878ecad536c4bbbf198ba0038d6`.
The final Clippy-only reference cleanup does not change runtime arithmetic.
Native and WASM use Rust 1.98.0 release builds; the native wheel is SpiralTorch
0.4.27 with `extension-module,nn,wgpu`, exercised in Python 3.12.6. WASM uses
`webgpu` and wasm-bindgen 0.2.104.

[summary.json](summary.json) records every condition, runtime adapter, comparison
result, and SHA256/size of the raw fixtures and built wheel/WASM assets. Raw
checkpoints, logs and binaries remain in the local validation archive; they are
not duplicated into Git. The summary was checked against all eight original
browser records and the native/reverse fixtures, including exact resumed
checkpoint and record concatenation. The native fixture was rerun after the
reverse test was added and remained byte-identical to the one the browser used.

Follow [the shared-control recipe](../../../docs/resident_vision_zspace_control.md)
to rebuild and replay. For legacy compatibility, additionally set
`SPIRALTORCH_VISION_TRAINER_LEGACY_FIXTURE` to the retained v1 native fixture.
Set `SPIRALTORCH_VISION_CONTROL_REVERSE_REPORT` to a new file to retain reverse
comparison results. Output files/directories must be new, not overwritten.

This does not measure real-image policy benefit, throughput, peak memory,
resident Adam/momentum, full producer/consumer closed-loop restart, geometric
weight updates or cross-device/power-loss durability. The plain-SGD matched
real-image baseline remains the control for that next learning comparison.
