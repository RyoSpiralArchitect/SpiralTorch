# Topos Learning Bridge: Wiring Evidence

Date: 2026-10-02. Source: `fd50a207da6250805953833bb21d1c3ebd7e9eaf`.
This is a correctness/learning-path experiment, **not** a speed benchmark,
pretrained fine-tune or evidence of improved language quality.

## What Ran

- Rust core: 8 targeted tests; existing Rust NN layer: 7 targeted tests.
- Python: 10 actual-native-extension tests, zero skipped, including finite
  differences inside/outside saturation, broadcast VJP, stale-input rejection,
  empty/noncontiguous inputs, identity/off behavior, recipe snapshot ownership,
  safe-load state-dict/Adam continuation, real tiny HF loss and MPS transport.
- Browser: the same Rust forward and both VJPs match the native fixture exactly;
  finite-difference maximum error `1.2156062425106029e-5`. A 100-update scalar
  gate-fit loop reduces MSE from `0.4857680487` to `0.0035288455`. This synthetic
  target is generated by the same operator; it establishes trainability only.
- HF: three seeds, three controls, 24 updates each. A randomly initialized,
  frozen GPT-2 architecture has one block, width 16, two heads, vocabulary 16,
  no dropout. There is no downloaded model or dataset. Each train/development
  batch contains two length-eight periodic token sequences with different phases.
  HF owns the ordinary shifted causal-LM loss. Only 16 gate parameters learn.

The off arm stays fixed. The linear-gate arm has the same parameter count and
initial local gain as the unsaturated Topos recurrence. Both active arms use
Adam at 0.05 with the same inputs and update count, but are **not** compute-cost
matched. Topos uses strength 0.5, coupling 0.35, six iterations, saturation 0.001
and porosity 0.2. The small saturation was chosen to exercise the nonlinear branch,
not selected for development loss. The adapter starts as an exact identity.
Every frozen base parameter is hashed before/after and unchanged; base hashes
match across arms within a seed. Repeating the complete final-source run produced
byte-identical `learning.json`.

## Results, Including The Negative Control Comparison

| Seed | Initial train CE | Linear final train CE | Topos final train CE | Linear dev change | Topos dev change |
| --- | ---: | ---: | ---: | ---: | ---: |
| 17 | 2.790863 | 2.784236 | 2.789892 | +0.001911 | +0.000301 |
| 29 | 2.798426 | 2.782108 | 2.796572 | -0.003716 | +0.000264 |
| 43 | 2.781461 | 2.771320 | 2.780461 | -0.006371 | -0.000342 |

All active gates receive gradients and change logits. On the final actual MLP
input, Topos differs from its linear-gain control by more than `1e-7` at
160/186/141 of 256 values, with maximum differences 0.004087/0.005129/0.005435.
Thus the nonlinear rewrite is used, not just an inactive decoration.

However, **the linear gate lowers training loss more in every seed**, and
Topos development CE worsens in two seeds. These tiny overlapping-pattern batches
cannot establish generalization. No optimum, statistical significance, pretrained
FT benefit, or advantage over LoRA is claimed. A real pretrained model, disjoint
data, fixed controls and an honest extra-cost measurement are the next gates.

## Artifacts And Reproduction

`learning.json` includes all arms, every loss/gradient observation, final gates,
base hashes, recipes and the native fixture. `browser.json` includes the full
browser learning trajectory. `provenance.json` binds source/artifact/log hashes
and validation outcomes; `SHA256SUMS` covers the public files. Executables and
raw local logs are retained locally, not committed.

From a clean source checkout in an isolated environment with Torch and
Transformers (recorded versions 2.12.1 and 4.57.6; Python 3.12.6):

```bash
maturin develop --manifest-path bindings/st-py/Cargo.toml --no-default-features --features python-default,cpu
python -m pytest bindings/st-py/tests/test_geometry_autograd.py -v -rs
python bindings/st-py/examples/topos_resonator_learning.py --steps 24 > learning.json
cargo test --locked -p st-core --lib topos_resonator
cargo test --locked -p st-nn --lib topos_resonator
```

For the browser, build `spiraltorch-wasm` for `wasm32-unknown-unknown` and run
matching `wasm-bindgen --target web` (recorded 0.2.104). Serve an isolated directory
containing the generated module as `/module/spiraltorch_wasm.js` with its adjacent
WASM/snippet files, the native report as `/learning.json`, and
`bindings/st-wasm/tests/topos_resonator_learning.html` as `/index.html`.
The page exposes pass/fail and numeric results in `#result`, without a GPU.
The published local build used default Python features, but this operator does
not require a GPU feature. Ambient automatic Torch/NumPy patching was disabled.

Rust 1.98.0 builds, pinned workspace formatting, core strict Clippy and the new
Python files' Ruff checks passed. **Whole wasm32 strict Clippy did not pass:**
19 findings remain in unchanged COBOL, cosmology, fractal, scale-stack, FFT and
Mellin files. This is not reported as a clean WASM lint run. WASM compilation and
the actual browser test passed. CUDA, higher-order gradients, AMP and resident
WGPU geometry were not tested or claimed.
