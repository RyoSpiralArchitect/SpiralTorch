# Native declared-set learning in Node and Chrome

One portable WASM build with `nn` (not WebGPU), Rust 1.99.0, wasm-bindgen
0.2.129. Node 24.14.0 and headless Chrome 157.0.8103.79 executed the same
four artificial controls. No pretrained model calls, training corpus, held-out
scores or performance benchmark. The public API calls st-nn's decoder and
finite acceptance check; JavaScript supplies the data and inspects the result.

| Artificial control | Rust decision | Proposed P(set) | Returned P(set) |
| --- | --- | ---: | ---: |
| Nonopposing repair component | Repair and accept | 0.66762804 | 0.66762804 |
| Exact opposition | Infeasible; throws | n/a | original 2/3 |
| Two outsiders, distance 1/65536 | Accept | 0.50039048 | 0.50039048 |
| Same outsiders, distance 1/128 | Reject | 0.00320050 | original 0.50000000 |

The clients recomputed the two losses from actual next-token logits, checked
both decisions against the native fixture, verified the separate proposed and
returned identities, and reloaded each returned artifact. The three artifacts
exported from Node/WASM (two updated, one unchanged) were also loaded **by
Python**: maximum absolute difference in logits and component scores was zero
against both the selected WASM model and the native reference. The fourth
control produced an error, not an artifact. Multi-window shifted supervision,
masked labels and undeclared targets were checked separately.

The initial WASM compile identified a host-only N-D synchronous read in the
new binding. The final implementation uses the decoder's own final-position
host logits instead; it does not block on a device read. Native regression:
303 Rust causal-LM tests and 70 installed Python binding tests. The fixture
regenerated byte-for-byte (SHA-256
`064f076226c662d08d30e41a65db3fb1596696c4da0c2731090612908148dfae`).
See the [reproduction and handoff instructions](../../../../../bindings/st-wasm/tests/native_causal_lm.md).
