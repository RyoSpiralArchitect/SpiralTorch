# Packaged WASM Saved-Checkpoint Selection

The source client now imports retained checkpoints through
`study.checkpointCandidates()`, `candidates.appendJson(opaqueJson)` and
`candidates.selectCheckpoint(caseName, policy)`. The collection owns its Rust
study and checkpoints. The result owns the existing geometry-bearing artifact,
including model optimizer history, plus Rust's weight-free decision JSON.

The selection rule, model math, training recipe, serving policy and numerical
gates are unchanged. A shared Rust constant supplies the 32-candidate limit to
the native selector and both bindings. Python retains its bounded iterator API.
The WASM collection checks the combined 64 MiB canonical budget during import;
the core selector still validates every candidate and history.

## Validation

- Native CPU Rust byte-study tests: **71 passed**, including all four selection
  tests. Python's CPU binding configuration passes `cargo check`; this is not
  a rebuilt Python wheel or a PyPI release.
- Fresh `nn` and `webgpu` packages pass respectively 20/30 existing transport
  checks plus **26 synthetic selection checks**. Generated and handwritten
  TypeScript contracts compile for Node and browser glue. CI requires the
  selection fixture explicitly; older transport fixtures retain their old CLI
  behavior.
- The prior qualified run's four saved cursors **0/4/8/12** were loaded from its
  sealed Python store, without retraining. Across **nine real saved models**,
  both WASM builds reproduce the Python decision JSON and artifact bytes exactly.
  Each passes 31 selection/lifetime checks. All nine choose cursor 12, as before;
  this is not a new early-stopping win.
- Actual browser WebGPU restoration of all nine selected artifacts reproduces
  direct-import logits and four-byte greedy generation exactly. Model outputs
  remain distinct across the ordinary, learned and frozen cases. Selection makes
  zero adapter requests; subsequent inference uses one shared adapter request.
  Physical browser hardware remains unverified.

Raw corpus, requests, snapshots, weights and generated bytes remain private.
Only bounded results, metrics, source/package/log hashes and reproduction
instructions are retained here. The older strict long-run Key-bias comparison
still fails and is not superseded. No language-quality or speed advantage is
established by transporting the selected model correctly.

## Review Boundary

The first independent read-only review found that passing two exported Rust
handles in one generated WASM call could strand the first owner's borrow if the
second handle was disposed. The unreleased API was redesigned rather than
patching generated glue or accepting raw pointers. The collection now owns its
study, imports opaque strings, and never accepts a second borrowed handle.

Regression tests include disposed input rejection followed by valid reuse and
cleanup, collection disposal without damaging the study, independent result
ownership, and string-prototype instrumentation. String ingress snapshots
validated UTF-8 using captured intrinsics rather than the generated
`passStringToWasm0` character lookup. Both intermediate failures are retained
locally. Final independent re-review did not complete because its tool returned
an execution error; the change remains a draft, not a reviewed merge approval.

## Reproduce

Use Rust 1.99.0, wasm-bindgen 0.2.129 and TypeScript 5.9.2. Build with `nn` and
`webgpu` separately and generate Node/browser glue. Keep each package before
building the other feature variant. For each Node package:

```sh
python3 -I -S -B bindings/st-wasm/tests/byte_lm_fixture.py > "$PRIVATE/synthetic.json"
node bindings/st-wasm/tests/byte_lm_node.mjs "$PACKAGE/spiraltorch_wasm.js" \
  "$PRIVATE/synthetic.json" nn selection
node bindings/st-wasm/tests/byte_lm_selection_types.cjs "$PACKAGE/spiraltorch_wasm.js"
```

Use `webgpu` instead of `nn` for that build. The private real-model fixture
requires the unchanged request and sealed run from the
[prior selection qualification](../2026-10-18-language-mlops-integration/README.md):

```sh
QUALIFIED_VENV/bin/python -I -B benchmarks/results/2026-10-18-wasm-checkpoint-selection/prepare.py \
  --run "$RETAINED/python-selection-reviewed" \
  --previous "$RETAINED/python-selection-reviewed.json" \
  --synthetic "$PRIVATE/synthetic.json" --output "$PRIVATE/retained.json"
node bindings/st-wasm/tests/byte_lm_node.mjs "$PACKAGE/spiraltorch_wasm.js" \
  "$PRIVATE/retained.json" webgpu selection
python3 -I -S -B benchmarks/results/2026-10-18-wasm-checkpoint-selection/stage_browser.py \
  --repo "$PWD" --package "$WEB_PACKAGE" --fixture "$PRIVATE/retained.json" \
  --output "$PRIVATE/browser"
python3 -I -S -B benchmarks/results/2026-10-18-packaged-language-mlops/qualify.py serve \
  --repo "$PRIVATE/browser/site" --package "$WEB_PACKAGE" \
  --output "$PRIVATE/browser" --port 8826
```

Open the loopback page once. The existing allowlisted server freezes only the
selected test assets, package and private fixture; result writes are exclusive.
It does not expose the repository or other experiment directories.

`publish.py --repo REPO --private PRIVATE --output NEW_RESULTS` checks complete
case coverage, exact selection identities, frozen assets and receipt boundaries
before writing sanitized results exclusively. Receipts are consistency evidence,
not independent attestation, model promotion, remote CI or release publication.
The manifest's `results` hashes identify the published JSON bytes; separate
`source_receipts` hashes identify the original private receipt bytes before
formatting. Run `python3 -I -S -B test_publish.py` from this directory to check
the serialization and private-payload rejection boundaries.
