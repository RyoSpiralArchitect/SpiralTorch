# Packaged Geometric Language MLOps

This milestone moves the Rust byte-LM lifecycle into the real `spiraltorch-wasm`
package. It does not change attention, geometry, optimizer math or acceptance
thresholds. Python and the packaged browser now consume the same Rust-owned
study, immutable artifact and measured-serving semantics. The standalone WASM
examples remain qualification adapters, not the only browser entry point.

The [API guide](../../../docs/wasm_byte_language_mlops.md) covers CPU transport,
actual WebGPU study/resume, artifact inference, generation, candidate preparation,
activation and rollback. Geometry encoders and head/query routers are executable
parts of the retained artifact, not independently reconstructed JS policy.

## Fixed Conditions

No new corpus, winning seed, geometry, tolerance or serving limit was selected.
Private input hashes are pinned in [inputs.json](results/inputs.json).

1. Restore all three width-16, seed-11, 1,024-update models from the preceding
   [Attention repair](../2026-10-18-language-vjp-isolation/README.md): ordinary,
   learned Poincare and identically initialized frozen Poincare geometry.
   Run the first saved validation window and four greedy bytes per row through
   packaged inference. The prior full-study strict Torch gate remains **failed**;
   successful artifact execution does not retroactively qualify that study.
2. Reuse the historical 128-update query-router candidate and its fixed
   [three-cohort mechanics gate](../2026-10-15-language-serving-cohorts/README.md).
   Each cohort has eight batches, two rows and 32 next-byte targets per row.
   The +2 CE regression limits are intentionally permissive mechanics controls,
   not production thresholds. A separate -100 mean-regression negative control
   must reject one cohort without switching the owner.
3. Rerun the original [small AdamW request](../2026-10-15-byte-study-optimizers/README.md)
   unchanged: seeds 11/29/47, ordinary/learned/frozen arms, B=2, T=8, width=8,
   hidden=16, two heads, 12 updates. Pause separately at update 5, then resume
   on a fresh browser page to 12 and compare with uninterrupted execution.
   Compare the final package result to the retained original Torch reference.

Raw corpus bytes, parameters, optimizer moments, generated bytes and checkpoints
remain private. Public receipts contain all selected conditions' metrics,
checks and hashes, not only a favorable case. Hashes are provenance aids, not
authentication or independent proof of computation.

## Results

- **101 browser checks passed** using the generated package, including opaque
  identity, strict ingress, live-versus-measured logits, foreign/stale/ABA permits,
  rejected activation, bit-exact rollback, busy-operation recovery and immediate
  handle release while work is pending. Shared/detached storage and coercion
  objects are rejected. Cross-realm and shadowed-property byte views work.
- All three restored 1,024-update artifacts produced distinct finite logits.
  Generated first bytes matched an independent argmax of their actual full
  forwards. Prompt hashes confirm input snapshots precede returned promises.
- The historical query-router candidate passed all three unchanged mechanics
  cohorts. One-cohort rejection did not change the live owner; rollback restored
  the original output hash and CE exactly. The package requested one adapter
  across these sequential mixed clients. This does not test concurrent cold-start
  device-request deduplication.
- All nine AdamW cases finished 12 updates. Fresh-page 5-to-12 resume reproduced
  the **complete report and checkpoint byte-for-byte**, including optimizer and
  frozen geometry state. See [resume.json](results/resume.json).
- All nine final models passed the existing Torch numerical checks, including
  geometry deltas and AdamW moments/clocks. Maximum parameter error was
  2.577e-6; no tolerance changed. See [torch-comparison.json](results/torch-comparison.json).
- CPU-only `nn` and `webgpu` builds passed 20 and 30 shared Node transport checks,
  respectively, plus explicit export-feature assertions. The no-feature WASM
  build passed `cargo check`. Rust byte-study tests: 81 passed with runtime
  opt-ins disabled; skipped GPU bodies are not additional runtime evidence.
- Three synthetic HTTP regressions passed: foreign-Host rejection, hash-checked
  frozen assets, and origin-bound/exclusive/frozen result transport.

The actual browser adapter reports `BrowserWebGpu`, device type `Other`.
Physical hardware execution remains unverified. This is not a performance
benchmark, a durable deployment service, an HF integration or a release upload.
The latest inspected parent PR CI run is still the unstarted October 15 failure;
local checks are not a substitute for green latest-head CI.

**No geometric quality gain is established.** In the 12-update comparison both
geometric arms remain worse than the ordinary arm at every seed. Learned versus
frozen geometry improves slightly at seeds 11/29 and worsens at 47. The single
window from the restored 1,024-update models is an execution check, not a new
held-out comparison or a reason to overturn the earlier failed strict gate.

## Reproduce

Use Rust 1.99.0, wasm-pack 0.14.0 and matching wasm-bindgen 0.2.129. These are the
recorded tools, not a claim that they are the newest releases. The generated
WebGPU package is pinned in the input manifest. Build a separate `nn` package
with the same command and `--features nn` to check CPU-only exports.

```sh
RUSTUP_TOOLCHAIN=1.99.0 wasm-pack build bindings/st-wasm --target web \
  --out-dir ../../target/packaged-byte-mlops-final --release -- --locked --features webgpu

# REQUEST/CHECKPOINT: final learning-reviewed companions from the prior study.
# LEARNING: unchanged 12-update v9 AdamW request; SERVING: historical v2 fixture.
# PRIVATE must be a new directory outside the checkout. PACKAGE is absolute.
python3 -I -S -B benchmarks/results/2026-10-18-packaged-language-mlops/qualify.py prepare \
  --repo "$PWD" --package "$PACKAGE" --output "$PRIVATE" \
  --request "$REQUEST" --checkpoint "$CHECKPOINT" \
  --learning-request "$LEARNING" --serving "$SERVING"
node bindings/st-wasm/tests/byte_lm_node.mjs "$PACKAGE/spiraltorch_wasm.js" \
  "$PRIVATE/input.json" webgpu > "$PRIVATE/node-webgpu.json"
node bindings/st-wasm/tests/byte_lm_node.mjs "$NN_PACKAGE/spiraltorch_wasm.js" \
  "$PRIVATE/input.json" nn > "$PRIVATE/node-nn.json"
python3 -I -S -B benchmarks/results/2026-10-18-packaged-language-mlops/qualify.py serve \
  --repo "$PWD" --package "$PACKAGE" --output "$PRIVATE" --port 8814
```

Open `http://127.0.0.1:8814/`, wait for `passed`, then open `/?phase=resume`.
The manifest-bound, frozen-asset loopback server writes private results exclusively, never
overwriting an earlier run. It supplies COOP/COEP for shared-buffer rejection
tests and exposes only the fixture, test assets and selected package files.
It is a local qualification server, not a public deployment endpoint.

```sh
jq -r .report_json "$PRIVATE/training.json" > "$PRIVATE/learning.json"
python3 -I -B tools/byte_corpus_study.py compare "$LEARNING" "$TORCH_REFERENCE" \
  "$PRIVATE/learning.json" "$PRIVATE/torch-comparison.json"
python3 -I -S -B benchmarks/results/2026-10-18-packaged-language-mlops/qualify.py verify \
  --repo "$PWD" --package "$PACKAGE" --output "$PRIVATE"
cargo +1.99.0 test --locked -p st-nn --no-default-features --features wgpu \
  --lib resident::byte_study:: -- --test-threads=1
```

`verify` binds receipts to source/package hashes, private fixture identity and
full training/resume payload hashes, and screens public receipts for private
payload fields. It is not an independent replay or training attestation. See
[verification.json](results/verification.json) and [review dispositions](REVIEW.md).
