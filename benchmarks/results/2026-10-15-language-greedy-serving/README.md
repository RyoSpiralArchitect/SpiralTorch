# Selected-Model Byte Generation

This records **mechanics plus a negative generation observation**, not a language
quality win. The new shared Rust loop executes the selected model rather than
reconstructing its geometry in Python/JS. Installed Python/Metal and actual
BrowserWebGpu were each checked against independent full-forward decoding.

## Fixed Comparison

Reuse the exact private `serving-input.json` from the
[named-cohort qualification](../2026-10-15-language-serving-cohorts/). No new
training updates, prompt search, parameter fitting or threshold changes.

- One historical seed (11), browser-trained checkpoint at update 128, two models:
  `seed11_ordinary` and `mixture-11-0-train-query-train` (Poincare/chord query mixture).
- B=2, T=32, width=16, heads=2, one block. Use the first T input bytes of each
  already-selected T+1 evaluation window, then produce exactly 32 new bytes.
- Greedy maximum, lowest byte ID on ties; reset positions/geometry at each sliding
  window. No EOS, temperature, sampling, repetition penalty or text cleanup.
- Bootstrap ordinary, activate the candidate after the existing explicit gate,
  then roll back. Every phase is independently replayed through full logits with
  dummy target 255, while the Rust loop uses dummy target 0.

## Observed Output

Both models, both clients and the restored model generated exactly:

| Row | Actual 32 output bytes |
| --- | --- |
| 0 | `0x20` repeated 32 times |
| 1 | `0x65` (`e`), followed by `0x20` repeated 31 times |

That is 63 spaces out of 64 generated bytes per phase. The selected candidate's
next-byte logits changed, but its greedy continuation did not. These tiny
128-update models passing the permissive teacher-forced cohort gate did **not**
produce useful prose on these prompts. Independent decoding agreement excludes
a discrepancy in this loop's byte selection/window shifting, not every possible
model/training issue. There is no general conclusion about geometry or larger
models from one seed and two prompts. Do not tune away or omit this observation.

Both clients verified exact generated bytes and all 32 per-step next-logit hashes
against their own full-forward oracle, rejected stale generation dispatches,
and recovered the original bytes/hashes after rollback. Across native and browser,
output bytes agree in every phase. Ordinary/rollback score hashes agree at all
32 steps; candidate score hashes agree at **0/32** steps. Cross-backend bitwise
identity is not required or claimed, even when the chosen bytes happen to agree.

`native-receipt.json`, `browser-receipt.json` and `validation.json` contain results,
checks and hashes only. Corpus windows, weights, raw study checkpoints, candidate
wheels and WASM binaries remain in the private local archive. Output bytes can
themselves contain sensitive material; publication here is a deliberate reviewed
choice, not a feature of the decoder or verification helper.

## Reproduce

Build and install a source candidate with WGPU using the
[build guide](../../../docs/python/build-and-validation.md). Candidate wheels
retain 0.4.31 metadata for local verification only; never upload them over the
immutable public 0.4.31 release. With the private, separately pinned input:

```sh
python -I -B benchmarks/results/2026-10-15-language-greedy-serving/verify_generation.py \
  --input /private/serving-input.json --output /private/generation.json --new-bytes 32
```

The helper consumes trusted private selection IDs; input self-consistency is not
authentication. It does not choose thresholds or make a durable deployment.
Build `resident_byte_learning_browser` for wasm32 with WGPU, generate matching
wasm-bindgen Web bindings, and open `crates/st-nn/tests/byte_generation_browser.html`
through the same private allowlisted loopback layout as the previous serving
qualification. Its download is the actual browser receipt, not a Node simulation.
This standalone WASM example is not yet a packaged `st-wasm` API.

The next learning comparison should include free-running repetition alongside
teacher-forced CE, before interpreting lower CE as usable generation. This result
does not justify a default geometry, a new sampling trick or a model promotion.
